## 3. Потоковая модель: где реальные грабли

### 3.1 Буферизация — КЛЮЧЕВО

Ты **обязан** думать не «захват → encode → send», а:

```

```

Причины:
- `waveIn` callback **не должен блокироваться**
- `send()` может блокироваться
- `lame_encode_buffer_interleaved()` иногда кушает больше времени, чем один аудиофрейм

Минимум:
- 2–4 PCM буфера
- размер ~20–50 мс каждый

- 44100 Hz
- 16 bit
- mono

- mono = в 2 раза меньше трафика
- проще энкодеру
- меньше latency

## 1. КРИТИЧНОЕ (то, что реально легко забыть)

### 1.1 Инициализация Winsock
Банально, но забывается:

- `WSAStartup(MAKEWORD(2,2))`
- корректный `WSACleanup()`

И **не** смешивать `close()` и `closesocket()`.

---

### 1.2 Таймауты сокета
Если сеть умерла, `send()` может:
- зависнуть навсегда
- или возвращать `WSAEWOULDBLOCK`

Нужно:
- `setsockopt(SO_SNDTIMEO)`
- возможно `TCP_NODELAY` (не обязательно, но полезно)

Иначе твой encoder thread может зависнуть, а ring buffer переполнится.

---

### 1.3 Partial send()
Ты **обязан** учитывать, что:

```
send(sock, buf, len, 0) != len
```

Особенно под Windows.

MP3-фреймы **нельзя резать произвольно**, поэтому:
- либо loop до полного send
- либо собственный send-buffer

---

### 1.4 Icecast может закрыть сокет «молча»
При:
- неверном auth
- неправильных заголовках
- убийстве стрима админкой

Первый `send()` после этого даст `ECONNRESET`.

👉 Это надо трактовать как:
> «стрим мёртв → реконнект → kill mount → start again»

## 1. Про «MP3-фреймы можно резать произвольно»

> MP3 — просто stream bytes

  - либо сохранить хвост
  - либо дослать его позже

Это не про «нельзя резать», а про:
> **нельзя терять байты**

📌 Поэтому правильная формулировка:
- ❌ нельзя *дропать* фреймы

## 3. Лучший «монотонный» источник времени под Win7

### 🥇 `QueryPerformanceCounter`

Это **де-факто CLOCK_MONOTONIC для Win32**.

Свойства:
- монотонный
- высокая точность
- не зависит от системного времени
- работает с WinXP+

Пара:
```c
QueryPerformanceCounter(&t);
QueryPerformanceFrequency(&freq);
```

📌 Использовать ТОЛЬКО для:
- логов
- статистики
- drift detection
- underrun timing

**Не для синхронизации аудио**, а именно для диагностики.

- 1–15 ms разрешение
- зависит от system timer resolution
- может прыгать

- Linux → clock_gettime

И **везде возвращать nanoseconds**.

Правильная модель:

```
        sleep_a_bit();
    }

```

Где:
- `encoder_block_size` = например 20–40 ms PCM
- `sleep_a_bit()` = `Sleep(1)` или `WaitForSingleObject(event)`

- encoder thread ≈ consumer с ограниченной скоростью

```
2. close socket
3. discard:

6. wait prebuffer (0.5s PCM)

8. resume encode+send
```

- логов

- Icecast переживает до ~100 ms
- TCP иногда подвисает на ~200–500 ms
- 1 секунда:
  - не слышна пользователю
  - не создаёт заметного time-shift
  - даёт шанс не рвать стрим при микролаге

> Всё, что больше 1–2 секунд, — уже **time travel**.

```c
#define BITS_PER_SAMPLE 16

#define PCM_FRAME_BYTES (SAMPLE_RATE * FRAME_MS / 1000 * CHANNELS * 2)

#define RING_SECONDS    2
#define RING_BYTES      (SAMPLE_RATE * RING_SECONDS * CHANNELS * 2)

#define WAVE_BUFFERS    20

/* ===================== GLOBAL STATE ===================== */

static volatile int g_running = 1;

static uint8_t ring_buffer[RING_BYTES];
static size_t ring_head = 0;
static size_t ring_tail = 0;

static pthread_mutex_t ring_mutex = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t  ring_cond  = PTHREAD_COND_INITIALIZER;

/* ===================== SIGNAL ===================== */

static BOOL WINAPI console_handler(DWORD sig)
{
    fprintf(stderr, "[signal] Console signal %lu received, shutting down\n", sig);
    g_running = 0;
    pthread_cond_broadcast(&ring_cond);
    return TRUE;
}

/* ===================== RING BUFFER ===================== */

static size_t ring_available(void)
{
    if (ring_head >= ring_tail)
        return ring_head - ring_tail;
    return RING_BYTES - ring_tail + ring_head;
}

static size_t ring_free(void)
{
    return RING_BYTES - ring_available() - 1;
}

static void ring_write(const uint8_t *data, size_t len)
{
    pthread_mutex_lock(&ring_mutex);

    if (len > ring_free()) {
        fprintf(stderr, "[ring] OVERFLOW, dropping %zu bytes\n", len);
        pthread_mutex_unlock(&ring_mutex);
        return;
    }

    for (size_t i = 0; i < len; i++) {
        ring_buffer[ring_head] = data[i];
        ring_head = (ring_head + 1) % RING_BYTES;
    }

    pthread_cond_signal(&ring_cond);
    pthread_mutex_unlock(&ring_mutex);
}

static size_t ring_read(uint8_t *out, size_t len)
{
    pthread_mutex_lock(&ring_mutex);

    while (g_running && ring_available() < len) {
        pthread_cond_wait(&ring_cond, &ring_mutex);
    }

    if (!g_running) {
        pthread_mutex_unlock(&ring_mutex);
        return 0;
    }

    for (size_t i = 0; i < len; i++) {
        out[i] = ring_buffer[ring_tail];
        ring_tail = (ring_tail + 1) % RING_BYTES;
    }

    pthread_mutex_unlock(&ring_mutex);
    return len;
}

        waveInAddBuffer(hwi, hdr, sizeof(*hdr));
    }

    lame_set_num_channels(lame, CHANNELS);

        waveInAddBuffer(hwi, &headers[i], sizeof(WAVEHDR));
```

## 2. Правильная модель backlog (строго)

## 2. Флаги сокета — что и зачем

### ✅ TCP_NODELAY — **ОБЯЗАТЕЛЬНО**
Отключает Nagle.

Почему:
- MP3-фреймы маленькие (≈500–700 байт)
- Icecast нормально ест поток байт
- задержки из-за coalescing недопустимы

```c
int yes = 1;

```

---

### ⚠️ SO_SNDBUF — **уменьшаем**, а не увеличиваем

По умолчанию Windows может поставить **сотни килобайт** — это плохо:
- TCP начнёт аккумулировать
- backlog перестаёт быть честным
- ты узнаешь о проблеме слишком поздно

Рекомендация:
- 32 KB или 64 KB — **верхний разумный предел**

```c
int sndbuf = 64 * 1024;
setsockopt(sock, SOL_SOCKET, SO_SNDBUF, &sndbuf, sizeof(sndbuf));
```

> Да, Windows может округлить — это нормально.

---

### ✅ SO_SNDTIMEO — **очень полезен**

Это твой «предохранитель от вечного send()».

Если сеть умерла:
- `select()` может показать writable
- `send()` может зависнуть
- `SO_SNDTIMEO` гарантирует выход

Рекомендация:
- 1000 ms (строго соответствует твоему backlog лимиту)

```c

```

Важно понимать:
- keepalive **не для realtime**
- дефолтные интервалы: **часы**
- Windows < 10 плохо настраивается

- можно включить как «last resort»

Текущее состояние ring buffer задаётся вот этим:


* `head == tail` → **буфер пуст**
* переполнение ты уже логируешь и дропаешь

## 2. Как ПРАВИЛЬНО сделать `ring_clear()` именно для ЭТОЙ реализации

### Ключевые требования из ТЗ

При reset стрима:

* ❌ нельзя отдавать старое аудио
* ❌ нельзя «дочитывать»
* ✅ encoder должен начать с *чистого настоящего*
* ✅ callback может продолжать писать
* ❗ никаких race’ов

### Минимально корректная реализация

```c
static void ring_clear(void)
{
    pthread_mutex_lock(&ring_mutex);

    ring_head = 0;
    ring_tail = 0;

    /* пробуждаем encoder, если он ждал данные */
    pthread_cond_broadcast(&ring_cond);

    pthread_mutex_unlock(&ring_mutex);

    fprintf(stderr, "[ring] cleared\n");
}
```

### Почему именно так

* `head = tail = 0`  
  → логически буфер пуст, **всё старое забыто**
* `memset(ring_buffer, …)` **НЕ НУЖЕН**
* `pthread_cond_broadcast`:
  - если encoder ждёт данные — он проснётся
  - увидит `shutdown/reset` флаг
